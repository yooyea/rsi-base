# 示例：修改参数后图表没有变化

这是说明准则如何落地的假设案例，未声称已在任何业务项目执行。

## 需要保持的性质

用户确认参数变更后，图表应按产品约定更新。取消编辑、撤销、保存及重新加载遵循各自约定，不假定所有参数变化都立即持久化。

## 读取事实

查看参数协议、状态来源、插件接口、计算或渲染入口，以及现有测试与 CI。先复现实际结果，不能直接把问题归因于未遵守架构。

## 建立保障

在权威协议定义数值、颜色等字段的含义；消费端直接使用协议，非法输入在约定边界被拒绝。

将插件访问宿主状态的允许路径变成边界检查，防止临时跨层补丁。

行为测试经过实际的参数编辑入口和实际渲染链路，验证确认后结果变化、取消后不提交、保存后重新加载一致等与此次变更相关的验收。可控数据隔离行情波动；外部服务替代部分须标明。

新增插件还需被测试发现机制覆盖。不能只为现有一个插件写死测试对象，却让后续插件全部漏检。

## 证明保障有效

在隔离副本中撤去参数到渲染的传播，确认用例因画面或计算结果未变化而失败；恢复后通过。检查不能只断言输入框、配置对象或内部函数被调用。

将相关测试接入候选版本 CI，并核实实际合入规则要求其结果。门禁失败时不能合入；未配置平台强制阻断时，明确记录该缺口。

## 交付与下一轮

要求部署时，对本次构建产物执行相应启动与行为验证，确认目标环境版本。保留真实结果，不以提交代码替代交付完成。

后续 Agent 通过统一协议、边界检查和行为回归得到反馈，无需再次依赖用户提醒同一个问题。发现误报或新盲区时维护原有保障，不不断叠加相同提示词。
