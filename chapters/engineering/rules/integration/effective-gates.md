# 有效的合入门禁

## 保障目标

让必要工程检查真实控制变更进入目标分支，避免未验证或失败的候选被误放行。

## 适用条件

建立、修改或审查 PR 工作流、结果汇总、仓库规则或自动合入路径时。

## 工程落实

分别核实检查逻辑、触发条件、执行版本、检查结果来源、必需检查配置及实际合入身份。提交 YAML 不代表平台规则已启用；没有相应读取权限时标记未验证。

汇总任务应在子任务失败时仍能执行。对必须执行的检查仅接受明确成功；不适用须由成功完成的范围判定得出，不能把取消、缺失、检测失败或异常跳过当成功。

验证准备合入的组合版本。主干前进时，根据项目并发风险使用最新基线重验或合并队列等机制。说明实际保证，不将一次合并候选检查称为永远覆盖最新主干。

规则文件、关键验收和工作流本身受独立于候选执行者的授权与审查约束。普通编码身份不得自行扩大权限或旁路门禁。单人仓库也需明确例外审批与留痕方式。

## 有效性验证

在授权的测试分支或仓库验证代表性失败：必要检查失败、取消、范围判定失败、结果缺失或过期时不能放行。验证成功候选可以按预期路径合入。

核对实际规则集与运行事件，不只检查工作流名称。反例测试没有执行时，只能报告静态配置检查。

## 边界

不自动授予合并或管理员权限。镜像同步、管理员旁路、紧急变更和常规 PR 分开核实；无法观察的上游流程不能假定已通过。门禁不证明尚未表达的需求正确。
